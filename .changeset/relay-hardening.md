Harden the relay (relay protocol contract v2.0.0, breaking for relay clients):
- `@decisionator/core`: request signatures now cover the full request target (path plus query string) and a mandatory per-request nonce: `"METHOD\nPATH_AND_QUERY\nTIMESTAMP\nNONCE\nSHA256_HEX(body)"`. `signRequest` adds an `X-Dcg-Nonce` header (fresh 128-bit value from the new `generateRequestNonce`). `verifyRequestSignature(method, pathAndQuery, timestamp, nonce, signature, key, body, { maxSkewMs, replayCache })` takes the nonce and an optional `RequestReplayCache`, which accepts each `(key, nonce)` pair once within the freshness window. New `generateInviteSecret` / `hashInviteSecret` helpers for invite binding.
- `@decisionator/relay`: invite and tunnel ids are 128-bit random (`inv_` / `tun_` + 32 hex chars). Invites are bound to an out-of-band secret: `POST /v1/docs/{docId}/invites` requires `secretHash`, and `POST /v1/invites/{inviteId}/accept` requires the matching `secret` and a `key` equal to the request signer (`403` otherwise), so knowing an invite id is no longer enough to receive the sealed project key. `WS /v1/docs/{docId}/live` requires a signed `subscribe` message from a current ACL member within 5 s, allows one subscription per connection, caps subscribers per doc (`maxLiveSubscribersPerDoc`, default 100) and drops subscribers removed from the ACL. Signed requests and WS hellos are checked against a replay cache. Mutating `/v1/*` routes are rate-limited per client IP and per signer key, and `/t/{tunnelId}/*` per IP and per tunnel (`429` with `Retry-After`; `rateLimits` option, `false` disables; `trustProxy` to use `X-Forwarded-For`). Existing databases gain an `invites.secretHash` column; pending v1 invites must be re-created.
